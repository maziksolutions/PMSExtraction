1. EXECUTIVE SUMMARY & PROCESSING ARCHITECTURE
================================================================================
The Maritime PMS Extraction Tool extracts maintenance jobs, inspection intervals,
and overhaul procedures from ship equipment instruction manuals and technical
specifications.

The extraction pipeline operates in two distinct operational modes:
  A. Text-Based Extraction:
     Used for digital PDFs where text can be directly extracted via PyMuPDF.
     Text is pre-segmented into chunks embedded with [PAGE N] and [CONTEXT PAGE N]
     markers.
  B. Vision-Based Extraction:
     Used for scanned / raster manuals or when text extraction yields insufficient
     data. Individual manual pages are rendered to PNG images, contrast-enhanced,
     and sent as multi-modal vision inputs to Claude.

Both modes feed into a post-processing and database ingestion pipeline that
normalizes frequencies, cleans formatting, attaches PDF and page references,
links jobs to parent machinery/components, consolidates duplicates, and assigns
standard maritime crew ranks (e.g., Chief Engineer, 2nd Engineer).

5. EXACT OUTPUT JSON SCHEMA & FIELD RULES
================================================================================
Claude must return ONLY a JSON array of objects following this strict schema:

[
  {
    "job_name": string (required),
    "job_code": string | null,
    "job_description": string | null,
    "safety_precaution": string | null,
    "frequency": integer | null,
    "frequency_type": "daily" | "weekly" | "monthly" | "yearly" | "hourly" | null,
    "is_critical": boolean,
    "source_page_number": integer | null,
    "confidence_score": integer (70 to 98)
  }
]

Field Details & Formatting Requirements:

1. job_name (String, max 500 chars):
   - Concise, specific maritime action + component name.
   - Example: "Check hydraulic oil level", "Overhaul brake cylinder", "Inspect V-belt tension".
   - Must NOT contain raw PDF filenames.
   - If manual is in Chinese/Japanese, must be translated to English.

2. job_code (String or null, max 100 chars):
   - Section number, table item number, or procedure identifier from the manual.
   - Examples: "5.1.2", "Item 4", "Sec 8.3".
   - Must NOT contain PDF filenames (e.g. "30# DECK.pdf" -> set null).

3. job_description (String or null):
   - Comprehensive procedure details and instructions.
   - LINE PREFIXING REQUIREMENT:
     Every single non-empty line must start with "/*-".
     Any sub-items (e.g. 1., 2., a., b., a), b)) must be broken into separate
     lines starting with "/*-".
     Example:
     /*-Isolate power supply and tag out breaker.
     /*-Drain hydraulic fluid from valve chamber.
     /*-1. Inspect O-ring seals for extrusion or hardening.
     /*-2. Clean spool bore with approved solvent.

4. safety_precaution (String or null):
   - Direct WARNING, CAUTION, or DANGER notices associated with the job.
   - Example: "DANGER: High pressure hydraulic fluid. Depressurize system before loosening fittings."

5. frequency (Integer or null):
   - The numerical interval value.
   - RANGE RULE: If interval is given as a range (e.g. 4-6 months, 500-1000 hrs, 1-2 years),
     MUST ALWAYS be the lowest integer (e.g. 4, 500, 1). Averaging is strictly prohibited.

6. frequency_type (String or null):
   - Allowed values: "daily" | "weekly" | "monthly" | "yearly" | "hourly".
   - Any other value is rejected and mapped to null.

7. is_critical (Boolean):
   - True if equipment is safety-critical, regulatory (SOLAS, MARPOL), propulsion-critical,
     or marked with WARNING labels.

8. source_page_number (Integer or null):
   - Exact integer matching the [PAGE N] marker or physical PDF page index.

9. confidence_score (Integer 70-98):
   - Self-assessed extraction quality score.

6. PRE-EXTRACTION CONDITIONS & CONTEXT INJECTION
================================================================================

1. Page Reference Filtering:
   - Extraction checks the manual's configuration columns:
     pages_with_jobs_physical (user-edited physical pages) -> fallback to pages_with_jobs.
   - Accepts discrete pages and ranges (e.g. "49-51, 60, 65-70").
   - If no page references are defined, job extraction skips the file.

2. Context Page Windows ([CONTEXT PAGE N]):
   - The system injects up to 2 preceding pages labeled with [CONTEXT PAGE N].
   - Instructions explicitly command Claude:
     "Do NOT extract any jobs or records from pages labeled with [CONTEXT PAGE N].
     Use them only to find the frequency or frequency context for jobs listed on
     the adjacent [PAGE N] pages."

3. Multilingual Handling:
   - For Asian language manuals (e.g. Chinese甲板机械, Japanese), the system prompt
     mandates direct translation to English. Non-Latin characters in output fields
     trigger automated stripping during post-processing.

7. POST-PROCESSING, SANITIZATION & NORMALIZATION RULES
================================================================================
Once Claude returns raw output, the backend applies the following Python rules:

1. JSON Parsing & Repair (_parse_json_records):
   - Strips leading/trailing markdown code blocks (```json ... ```).
   - If output was truncated before closing ']', automatically repairs the JSON
     structure to salvage completed records.

2. PDF Filename Cleansing (_clean_field_value):
   - Scans job_name, job_code, and other fields. If any field matches or contains
     the PDF filename (e.g., "Deck Machinery.pdf"), the field is wiped to null.

3. Frequency Range Resolution (parse_job_frequency):
   - Evaluates strings via regex: r"(\d+)\s*(?:[-~–—/]|to)\s*(\d+)".
   - Takes min(n1, n2) to ensure range lower-bound compliance.
   - Detects frequency units (hours -> hourly, months -> monthly, etc.).

4. Line Prefixing Enforcement:
   - Verifies that job_description lines adhere to the "/*-" prefix convention.

5. Source Reference Stamping:
   - Automatically appends source citation metadata to job_description:
     "Source: 30# DECK MACHINERY甲板机械.pdf (p.49)"

================================================================================
8. COMPONENT LINKING, CANONICAL NAMING & RANK ASSIGNMENT
================================================================================
After saving raw job records to the database:

1. Component Linking (_link_records_to_components):
   - Matches extracted jobs to Components belonging to the same manual based on
     equipment keywords, assembly context, and page proximity.

2. Canonical Job Naming (build_canonical_job_name):
   - Standardizes job naming structure across all vessels in the tenant:
     [Action Verb] + [Component Name] + [Interval/Specific Scope]
     Example: "Overhaul - Mooring Winch Hydraulic Motor (Annual)"

3. Crew Rank Assignment (backfill_manual_job_ranks):
   - Analyzes job description, safety precautions, and component criticality.
   - Automatically assigns maritime responsibility ranks:
     • C/E (Chief Engineer): Complex overhauls, safety equipment, propulsion.
     • 2/E (Second Engineer): Main engine overhauls, auxiliary engines, boilers.
     • 3/E (Third Engineer): Purifiers, compressors, pumps, generators.
     • 4/E (Fourth Engineer): Bunkering, basic filters, sewage plant.
     • E/O (Electro-Technical Officer): Automation, electrical panels, sensors.
     • Bosun / AB: Greasing, visual deck inspections, winches.

9. ERROR HANDLING, RETRY CONDITIONS & PROVIDER FAILOVER
================================================================================

1. Sufficiency Retry:
   - If message.stop_reason == "max_tokens" or the JSON array is partial, the API
     call is automatically retried with double the token limit (up to 64,000).

2. Provider Failover Chain:
   If Claude fails (billing, API down, or timeout):
   - Step 1: Claude (Anthropic claude-sonnet-4-6)
   - Step 2: OpenAI (gpt-4o-mini / gpt-4o fallback)
   - Step 3: Google Gemini (gemini-2.0-flash / gemini-1.5-pro fallback)

3. Billing Circuit Breaker:
   - If Anthropic returns an account credit / billing exhaustion error,
     a circuit breaker trips to avoid blocking other manual extractions.
